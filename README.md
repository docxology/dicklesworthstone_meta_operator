# Dicklesworthstone Meta-Operator

[![CI](https://github.com/docxology/dicklesworthstone_meta_operator/actions/workflows/ci.yml/badge.svg)](https://github.com/docxology/dicklesworthstone_meta_operator/actions/workflows/ci.yml)

Meta-operator over the entire [github.com/Dicklesworthstone](https://github.com/Dicklesworthstone)
corpus (~207 repos, ~10 GB cloned): clone every repo, confirm every clone sits on its
upstream default branch with a clean worktree, orchestrate commands across the
corpus, interpret each repo (languages, LOC, manifests, entry points, test
setup, README digests), and render a static dashboard + markdown catalog.

A self-contained fork of the
[`template_code_project`](https://github.com/docxology/template) conventions:
thin orchestrators in `scripts/`, logic in `src/`, zero-mock tests gated at
≥90 % branch coverage. No framework dependencies — the only subprocess
boundaries are `gh` and `git`, and the only runtime dependency is `pyyaml`.

Point it at any GitHub user: edit `data/operator_config.yaml` → `github_user`,
re-run the pipeline. The `output/` artifacts in this repository are snapshots
of a live run (2026-09-03) and are regenerated by the pipeline.

## Pipeline

| Stage | Script | Artifact |
| --- | --- | --- |
| 0 preflight | `scripts/00_preflight.py` | — (env checks) |
| 1 registry | `scripts/10_build_registry.py` | `output/data/repo_registry.json` |
| 2 clone | `scripts/20_clone_corpus.py` | `repos/` + `output/data/clone_outcomes.json` |
| 3 verify | `scripts/30_verify_upstream.py` | `output/data/upstream_status.json` |
| 4 inventory | `scripts/40_inventory.py` | `output/data/inventory.json` |
| 5 orchestrate | `scripts/50_orchestrate.py` | `output/data/runs/<id>/results.json` + `output/reports/<id>.md` |
| 6 dashboard | `scripts/60_dashboard.py` | `output/web/dashboard.html` + `output/data/corpus_catalog.md` |
| 7 gate | `scripts/70_health_gate.py` | `output/data/health_gate.json` |
| 8 figures | `scripts/65_generate_figures.py` | `output/figures/fig_*.png` (manuscript figures) |
| 9 tokens | `scripts/z_generate_manuscript_variables.py` | `output/data/manuscript_variables.json` |
| 9 sync | `scripts/90_sync_corpus.py` | run artifact + upstream state refresh |

Every stage is idempotent and re-runnable; failures print a fix hint.

## Quickstart

```bash
# From the template monorepo root (root venv owns the dependencies):
uv run python projects/ongoing/Code_Tools/dicklesworthstone_meta_operator/scripts/00_preflight.py
uv run python projects/ongoing/Code_Tools/dicklesworthstone_meta_operator/scripts/10_build_registry.py
uv run python projects/ongoing/Code_Tools/dicklesworthstone_meta_operator/scripts/20_clone_corpus.py   # long: ~10 GB
uv run python projects/ongoing/Code_Tools/dicklesworthstone_meta_operator/scripts/30_verify_upstream.py
uv run python projects/ongoing/Code_Tools/dicklesworthstone_meta_operator/scripts/40_inventory.py
uv run python projects/ongoing/Code_Tools/dicklesworthstone_meta_operator/scripts/60_dashboard.py
open projects/ongoing/Code_Tools/dicklesworthstone_meta_operator/output/web/dashboard.html
```

Orchestration examples:

```bash
# Sync the corpus with upstream (fast-forward-only pulls), then confirm:
uv run python .../scripts/90_sync_corpus.py

# Auto-detected pytest in the 5 newest Python repos:
uv run python .../scripts/50_orchestrate.py --auto test --language Python --sort recent --limit 5

# One command everywhere:
uv run python .../scripts/50_orchestrate.py --command "git log -1 --format=%h %s"
```

## Configuration

`data/operator_config.yaml` (versioned input): `github_user`,
`repos_dir`, `include_forks` (default true — the 8 third-party forks are
cloned and flagged; flip to false to operate on Dicklesworthstone's own work
only), worker counts, per-run timeout, captured stream tail size.

## The research manuscript

The repository ships a complete, artifact-backed research manuscript
(`docs/manuscript/`) describing the system's formalisms (the nine-state
verification machine, smart fetch, bounded source counting, the binary gate)
and reporting live corpus results. Its accuracy is mechanical: every number in
the prose is a `{{TOKEN}}` emitted from the tracked artifacts by
`src/manuscript_variables.py`, cross-checked in both directions by
`tests/test_manuscript_variables.py` — prose cannot drift from evidence
without a red CI run. Figures are generated deterministically by
`scripts/65_generate_figures.py`. See `docs/manuscript/SYNTAX.md` for the
label/token registries.
